# RMF 任务轨迹可视化 V0.2 需求文档

## 1. 目标

在不修改 RMF Web 现有页面和调度逻辑的前提下，提供独立的任务轨迹观测模块。模块接收 RMF 数据投影，统一为稳定的 Web 契约，并按原始时间戳完成历史回放和实时状态展示。

本版本解决两个问题：

1. 将演示接口替换为可被真实系统推送的接入层。
2. 将按路径点序号播放改为按时间戳插值播放。

## 2. 用户与场景

- 运维人员：查看机器人当前状态、连接新鲜度和任务执行指标。
- 调度分析人员：导入一段历史数据，按真实时间回放机器人位置与事件。
- 集成人员：通过 HTTP 推送 RMF 状态，不需要修改本模块前端。

## 3. 范围

### 3.1 本版本包含

- 统一轨迹数据契约 V1。
- RMF `FleetState`/`fleet_states` 单快照适配，包括嵌套车队、RobotMode 和 ROS `{sec, nanosec}` 时间。
- 多快照 `samples` 历史数据适配。
- 已规范化数据透传和校验。
- `POST /api/trajectory/live` 实时推送。
- 可选 Bearer Token 鉴权，读取 `RMF_INGEST_TOKEN`。
- 内存累积每台机器人最近 5000 个轨迹点，并报告连接状态和数据年龄。
- 基于时间戳的轨迹点插值、拖动、倍速和循环回放。
- 在线机器人、执行中任务、平均时延、重规划次数动态计算。
- 导入失败、请求失败、无数据和过期连接状态。

### 3.2 本版本不包含

- 直接订阅 ROS 2 DDS；应由部署侧 bridge 转为 HTTP 投影。
- rosbag2/MCAP 二进制文件解析。
- 持久化数据库和跨会话查询。
- 路径冲突、禁区入侵和路线偏离算法。
- 对 RMF 调度、任务和机器人发送控制命令。

## 4. 数据契约 V1

所有时间使用 ISO 8601 UTC 字符串或 Unix 毫秒。输出统一为 Unix 毫秒。

```json
{
  "schema_version": "1.0",
  "map": {"name": "L1", "width": 100, "height": 64},
  "robots": [
    {
      "id": "robot-1",
      "name": "robot-1",
      "fleet": "delivery",
      "battery": 82,
      "status": "moving",
      "task": "task-42"
    }
  ],
  "routes": {
    "robot-1": [
      {"x": 12.4, "y": 8.2, "t": 1787907600000},
      {"x": 13.1, "y": 8.2, "t": 1787907601500}
    ]
  },
  "events": [],
  "tasks": [],
  "zones": [],
  "meta": {
    "start_time": 1787907600000,
    "end_time": 1787907615000,
    "source": "rmf-http",
    "connected": true
  }
}
```

历史批量输入可使用：

```json
{
  "map": {"name": "L1", "width": 100, "height": 64},
  "samples": [
    {"timestamp": "2026-08-28T09:40:00Z", "fleet_states": []},
    {"timestamp": "2026-08-28T09:40:01Z", "fleet_states": []}
  ],
  "task_events": []
}
```

## 5. 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/health` | 服务健康状态和实时数据状态 |
| GET | `/api/trajectory/demo` | 带真实时间戳的演示历史数据 |
| GET | `/api/trajectory/live` | 最新实时数据；尚未推送时返回明确的演示降级状态 |
| POST | `/api/trajectory/live` | 推送规范化数据、单快照或批量快照 |
| POST | `/api/trajectory/import` | 规范化历史 JSON，不写入实时存储 |

## 6. 交互规则

- 历史模式以 `start_time` 到 `end_time` 为时间轴范围。
- 机器人位置取当前时间前后两个点做线性插值；无未来点时停在最后已知位置。
- 切换实时模式后每 5 秒拉取一次最新快照，时间定位到数据末端。
- 实时数据超过 15 秒未更新显示“数据延迟”，不伪装为正常连接。
- 导入完成后进入历史模式，指标、事件、任务表和地图同时更新。
- 任何网络或格式错误必须显示可理解的状态，保留上一帧数据。

## 7. 验收标准

- 非均匀时间间隔的轨迹能够按时间而不是按点序号插值。
- 多快照输入可以合并为每台机器人的有序轨迹。
- 实时 POST 后，GET 返回相同数据语义且健康接口显示已有实时数据。
- 指标和任务表不再使用页面硬编码值。
- 桌面和 390px 移动端无横向溢出，Canvas 非空。
- 服务继续从 `$PORT` 读取端口并绑定 `0.0.0.0`。
